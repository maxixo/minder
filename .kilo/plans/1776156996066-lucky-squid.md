# Dashboard Implementation Plan

## Goal

Implement the React dashboard page by translating the design and content from `dashboard.html` into the routed app page currently rendered by `client/src/pages/Home.tsx`.

## Current State

- `dashboard.html` contains a full standalone dashboard layout with its own header, top navigation, hero quote, KPI cards, wellness chart, recent entries, quick actions, mindful tip, media card, and footer.
- `client/src/pages/Home.tsx` is still a placeholder.
- The React app already wraps protected pages with `client/src/components/common/Layout.tsx`, which provides the page shell and left sidebar.
- `client/src/components/common/Sidebar.tsx` is still placeholder-level, so the app shell is incomplete, but it does already reserve layout space for page content.

## Recommended Direction

Port the dashboard *content* from `dashboard.html` into `client/src/pages/Home.tsx`, while keeping the existing routed app shell (`Layout` + `Sidebar`) intact.

Why this is the best fit:

- `App.tsx` already routes `/dashboard` through the shared layout.
- Reusing the shell avoids duplicating navigation chrome inside the page.
- The HTML file can be adapted into a dashboard content view rather than a second full-page app frame.

## Planned Work

1. Review the static HTML sections and map them into React-friendly page sections inside `Home.tsx`.
2. Extract the parts that belong inside page content only:
   - hero quote card
   - summary metric cards
   - weekly wellness chart block
   - recent journal entries list
   - quick action panel
   - mindful tip panel
   - meditation/media card
3. Omit or adapt the standalone `dashboard.html` header/footer/top nav so they do not conflict with `Layout.tsx`.
4. Replace placeholder text in `Home.tsx` with semantic JSX using existing Tailwind tokens from `client/tailwind.config.js` and shared utility classes from `client/src/index.css`.
5. Convert repeated UI parts into local arrays plus `.map()` where it improves readability, such as:
   - metric cards
   - weekday labels
   - journal entry cards
6. Keep the first implementation static, matching the source HTML content closely, without inventing new API dependencies.
7. Verify the page builds cleanly and visually fits within the current layout container.

## Implementation Notes

- The SVG wellness chart from `dashboard.html` can be copied directly into JSX with attribute names normalized for React (`strokeLinecap`, `stopColor`, etc.).
- `class` attributes must be converted to `className` throughout.
- Because the app already uses Tailwind and the required color families (`sage`, `sand`, etc.), most styles can be translated directly.
- The fixed width assumptions in `dashboard.html` should be softened where needed to fit the existing `Layout.tsx` main column.
- External image usage in the media card can remain as-is unless the user prefers local assets.

## Likely Files To Update During Implementation

- `client/src/pages/Home.tsx`
- possibly `client/src/components/common/Layout.tsx` only if spacing/container width needs a small adjustment to better match the dashboard composition

## Verification

- Run the client build to confirm JSX/Tailwind compatibility.
- Check that `/dashboard` renders correctly on desktop and mobile widths.
- Ensure the page does not duplicate global app navigation if the shared shell is retained.

## Open Decision

One implementation detail materially affects the result:

- **Recommended:** keep the existing React app shell (`Layout` + sidebar) and port only the dashboard body into `Home.tsx`
- **Alternative:** reproduce the full standalone `dashboard.html` page including its top header/footer and bypass or reshape the current shared layout

This decision determines whether the dashboard becomes a content page inside the app shell or replaces the shell for that route.
