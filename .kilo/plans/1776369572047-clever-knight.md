# Plan: Unify Sidebar Across Protected Pages

## Goal

Use the existing dashboard sidebar as the single protected-app navigation pattern across all main pages, replacing any page-specific sidebar implementations.

## Current State

- `client/src/components/common/Layout.tsx` already provides the dashboard sidebar via `Sidebar` and wraps most protected pages.
- `client/src/components/common/Sidebar.tsx` is the current shared dashboard sidebar component.
- `client/src/App.tsx` places `/dashboard`, `/selfcare`, `/emotional`, `/review`, `/analytics`, and `/settings` under `Layout`.
- `client/src/pages/DailyReflection.tsx` is the main outlier: it renders its own `<aside>` and uses a completely separate visual/navigation structure.
- `client/src/App.tsx` also routes `/reflection` outside `Layout`, which is why that page does not currently inherit the dashboard sidebar.

## Implementation Plan

1. Move `DailyReflection` under the shared protected layout.
   - Update `client/src/App.tsx` so `/reflection` is a child route of the `Layout` route instead of a separate top-level protected route.
   - This makes the dashboard sidebar render automatically for the reflection page.

2. Remove the page-specific reflection sidebar.
   - In `client/src/pages/DailyReflection.tsx`, delete the custom `sidebarLinks` config and the `<aside>` block.
   - Remove `Link` and `clsx` usage that exists only for that sidebar, keeping only imports still needed by the page body.

3. Normalize the reflection page container so it fits the shared layout.
   - Replace the page-level `min-h-screen` / two-column shell with a content container that assumes the sidebar already exists externally.
   - Preserve the reflection page's main content, top sticky header, save button, and footer where appropriate.
   - Adjust widths/margins so the page content aligns visually with the dashboard layout instead of trying to own the full viewport.

4. Keep the dashboard sidebar as the single source of navigation truth.
   - Do not duplicate navigation data inside pages.
   - If needed, only update `client/src/components/common/Sidebar.tsx` for label/order consistency, not page-local sidebars.

5. Verify responsive behavior after consolidation.
   - Confirm desktop uses the fixed left dashboard sidebar.
   - Confirm smaller screens continue using the existing mobile header behavior from `Sidebar.tsx`.
   - Confirm the reflection page no longer shows a second sidebar or conflicting left spacing.

## Files Expected To Change

- `client/src/App.tsx`
- `client/src/pages/DailyReflection.tsx`
- Possibly `client/src/components/common/Sidebar.tsx` if small nav consistency tweaks are needed after the route move

## Notes

- Most protected pages already satisfy the requirement through `Layout`; the main implementation work is consolidating `DailyReflection` into that shared structure.
- This is a minimal change path and avoids introducing a second shared layout or a new sidebar variant.
